### GIF 만드는 법

앱의 실제 뒤집기 애니메이션을 실시간 녹화하면 프레임 간격이 들쭉날쭉하다.
대신 앱에서 **앞뒤 정지 화면 두 장**을 찍고, 합성 페이지에서 회전각을 프레임마다
직접 지정해 찍는다 — 프레임 수·간격이 정확해진다.

### 왜 GIF 가 아니라 WebP 인가

말씀카드 배경이 그라디언트라 **GIF 로는 대각선 줄무늬(밴딩)** 를 피하기 어렵다.
GIF 는 프레임당 256색뿐인 인덱스 컬러 포맷이라 부드러운 색 변화를 담지 못한다.

| 방식 | 용량 | 그라디언트 |
|---|---|---|
| GIF 64색 (gifenc) | 118KB | 줄무늬 뚜렷 |
| GIF 256색, 디더 없음 | 238KB | **줄무늬 여전** — 색만 늘려서는 안 된다 |
| GIF 256색 + `dither=sierra2_4a` | 247KB | 해결되지만 무겁다 |
| **애니메이션 WebP q=82** | **76KB** | **원본과 구분 불가** |

WebP 는 풀컬러라 밴딩 자체가 없다. 만들기는 `img2webp` 한 줄이다 —
**`-lossy` 를 명시해야 한다.** 빼면 무손실로 인코딩돼 270KB 가 나온다(q 값이 먹지 않으면 이 경우다).

```bash
img2webp -loop 0 -lossy -q 82 -d 900 frame-000.png -d 50 frame-001.png … -o out.webp
```

호환성: 애니메이션 WebP 는 iOS 14+ · Chrome 32+ 에서 재생된다. 앱 WebView(카카오톡 인앱 포함)도
같은 엔진을 쓰므로 문제되지 않는다. 그보다 오래된 환경을 만나면 GIF 로 되돌리면 된다.

용량을 줄인 방법:
- 녹화 컨텍스트를 **`deviceScaleFactor: 1`** 로 (레티나면 픽셀이 4배)
- 정지 구간은 같은 프레임을 여러 장 넣지 않고 **concat 의 `duration`** 으로 표현하고
  `-fps_mode passthrough` 로 GIF 의 프레임별 delay 에 그대로 싣는다
  (fps 를 고정하면 0.9초·1.6초 정지가 같은 프레임 수십 장으로 펼쳐져 오히려 커진다)

프레임 생성 스크립트: 스크래치패드 `capture/notice-gif-ffmpeg.mjs` (프레임까지 만들고, 인코딩은 위 img2webp 로) · 정지 이미지는 `capture/notice-shots-v2.mjs`
(로컬 시드 계정으로 촬영: `./scripts/seed-dev.sh` → `/dev/login`)

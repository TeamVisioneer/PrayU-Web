### GIF 만드는 법

앱의 실제 뒤집기 애니메이션을 실시간 녹화하면 프레임 간격이 들쭉날쭉하다.
대신 앱에서 **앞뒤 정지 화면 두 장**을 찍고, 합성 페이지에서 회전각을 프레임마다
직접 지정해 찍는다 — 프레임 수·간격이 정확해진다.

### 이미지 포맷 — GIF 을 쓴다 (WebP 개선본도 함께 둔다)

말씀카드 배경이 그라디언트라 **GIF 로는 대각선 줄무늬(밴딩)** 가 생기기 쉽다.
GIF 은 프레임당 256색뿐인 인덱스 컬러라 부드러운 색 변화를 담지 못한다.
디더링(`dither=sierra2_4a`)으로 해결했고, 그 결과물을 쓴다.

WebP 도 만들어 비교했다. 첫 시도(`-lossy -q 82`)가 **화질이 물러 보인다는 지적**을 받아 원인을 확인했다 —
img2webp 의 문제가 아니라 **q=82 자체가 낮았다**. 첫 프레임을 뽑아 재보니 `cwebp -q 82` 와
용량·PSNR 이 완전히 같았다(44dB). 손글씨체 구절의 가장자리가 뭉개지는 게 그 수준에서 보인다.

| 파일 | 용량 | 원본 대비 |
|---|---|---|
| **`1.gif`** (사용 중) | 248KB | 256색 + 디더 — 밴딩 없음, 디더 노이즈 있음 |
| `1-q96.webp` | 140KB | PSNR 47.7dB — GIF 보다 44% 가볍다 |
| `1-lossless.webp` | 271KB | **PSNR ∞ (픽셀 단위 동일)** |
| ~~q=82~~ | 74KB | PSNR 43.9dB — **물러 보임, 쓰지 않는다** |

지금 GIF 을 쓰는 이유는 호환성이다. 화질만 보면 `1-lossless.webp` 가 GIF 보다 낫고 용량도 비슷하니,
WebP 로 가기로 하면 원고의 이미지 경로만 바꾸면 된다.

```bash
# 무손실 (원본과 동일)
img2webp -loop 0 -lossless -m 6 -d 900 frame-000.png -d 50 frame-001.png … -o out.webp
# 손실 (q 는 92 이상을 권한다. 82 는 물러 보인다)
img2webp -loop 0 -lossy -q 96 -m 6 -d 900 frame-000.png … -o out.webp
```

GIF 인코딩은 **ffmpeg** — `palettegen=max_colors=256:stats_mode=full` + `paletteuse=dither=sierra2_4a`.
순수 JS(gifenc)는 디더링이 없어 이 그라디언트에서 밴딩을 피하지 못했다.

용량을 줄인 방법:용량을 줄인 방법:
- 녹화 컨텍스트를 **`deviceScaleFactor: 1`** 로 (레티나면 픽셀이 4배)
- 정지 구간은 같은 프레임을 여러 장 넣지 않고 **concat 의 `duration`** 으로 표현하고
  `-fps_mode passthrough` 로 GIF 의 프레임별 delay 에 그대로 싣는다
  (fps 를 고정하면 0.9초·1.6초 정지가 같은 프레임 수십 장으로 펼쳐져 오히려 커진다)

프레임 생성 스크립트: 스크래치패드 `capture/notice-gif-ffmpeg.mjs` (프레임까지 만들고, 인코딩은 위 img2webp 로) · 정지 이미지는 `capture/notice-shots-v2.mjs`

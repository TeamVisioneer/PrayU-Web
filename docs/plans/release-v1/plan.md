# v1.0.0 릴리스 계획

> 상태: **범위 확정 중** — 피처 목록은 확보, 분할 판단 대기. v1.0.0 의 단일 기준 문서.
> 릴리스가 가까워지면 당일 절차를 `runbook.md` 로 분리한다 (지금은 4절 요약만).

## 왜 v1.0.0 인가

prod 는 v0.15.0(2025-07-12)에 멈춰 있고, 이후 1년치 개선이 전부 main(staging)에서 검증돼 왔다.
이번 릴리스는 **쌓인 것 전부 + 신규 피처 묶음**을 한 번에 내보내는 메이저 릴리스다.
릴리스가 늦어질수록 변경 뭉치는 더 커진다 — 신규 피처 범위를 빨리 닫는 것이 리스크 관리다.

## 1. 이미 main 에 있는 것 — 릴리스하면 자동 포함

상세·PR 번호는 각 레포 backlog "완료" 절. 여기서는 사용자 눈에 보이는 단위만.

- **말씀카드**: 생성·재생성/교체, 일일 한도, 카카오 공유 보상(+1회), 안내 시트, 히스토리 드로워
- **QT**: 페이지 개편(구절 픽커·범위 선택), LLM 일일 한도
- **공지 시스템**: DB 공지 + 전역 모달 + 목록 페이지, 어드민 저작·게시 절차(레포 원고)
- **어드민**: 대시보드 전면 개편(지표·퍼널), `is_admin` 접근 제어
- **성경 본문**: 원본(goodtv) 동기화 — 5,538행 교정, 누락 절 복구
- **스토리지**: 신규 업로드 R2 전환 (release 시 prod 자동 활성화 — 환경변수 등록 완료)
- **회원 탈퇴**: 소프트 삭제 전환(그룹장 이양 포함) — 기존엔 탈퇴가 조용히 실패했다
- **기반**: 뷰포트 dvh/safe-area, Toast UX, JWT 서명 검증, 죽은 엔드포인트 제거, `is_admin` 자기부여 차단

> 🔴 **SNS 전환은 v1.0.0 에 통째로 넣지 않기를 권한다.** 근거는 [sns/overview.md](../sns/overview.md) 5절 —

## 4. 릴리스 절차 (요약)

1. **staging 최종 인수** — 남은 것: 실기기 뷰포트·앱 WebView 회귀, 탈퇴 흐름 실계정 1회
2. **Api 태그 발행** → prod 마이그레이션 + 함수 배포
3. **운영 조작** (사람) — 🔴 관리자 `is_admin=true` · 카카오 웹훅 등록(POST) · `push` 함수 삭제 ·
   `KAKAO_ADMIN_KEY`·도메인 확인 — 전체 목록: [Api backlog "운영 조작 대기"](../../../../PrayU-Api/docs/backlog.md)
4. **web 태그 발행** → Vercel prod 빌드 (R2 여기서 켜진다)
5. **릴리스 후** — 공지 게시(레포 원고 준비됨) · prod 탈퇴 시도 이력 확인 · Sentry/analytics 모니터링

상위: [overview.md](overview.md) · 상태: **설계 확정 대기** (파일 매니페스트까지 작성됨, 구현 승인 전)

## 목표

```
[ 홈 ]  [ 그룹 ]  [  +  ]  [ 알림 ]  [ 프로필 ]
```

지금은 하단 네비게이션이 없고 화면 이동이 페이지마다 다르다(뒤로가기·드로워·버튼).
**v1.0.0 은 "기존 화면을 연결"하는 것까지만** — 새 화면은 만들지 않는다. 목적지가 전부 이미 있다.

## 탭 → 목적지 (전부 기존 라우트)

| 탭 | 목적지 | 비고 |
|---|---|---|
| 홈 | `/` (MainPage) | v1.2 에서 "오늘" 허브로 교체 예정 ([daily.md](daily.md)) |

| **+** | **액션 시트** — 기도카드 / 감사카드 / 말씀카드 | 새 개념 없이 기존 생성 경로 3개로 연결. 항목은 나중에 추가 |
| 알림 | `/notifications` (NotificationPage — 이미 있음) | 지금은 그룹 헤더 버튼으로만 진입 가능하던 화면 |
| 프로필 | `/profile/me` (MyProfilePage — 이미 있음) | |

## 노출 규칙

- **로그인 상태에서만 표시.** 비로그인은 기존 랜딩 경험 그대로 (네비 없음) — 보호 라우트 진입 시 기존 로그인 유도 흐름 재사용
- **숨기는 라우트**: 공유 랜딩(`/bible-card/share/*`, `/group/*/join`, open 계열) · 콜백(`/auth/*`, `/share/*`) ·
  약관(`/term*`) · 튜토리얼 · 어드민(`/admin*`) · Office(`/office/*`) · dev(`/dev/*`) · 생성 플로우 전체 화면(카드 작성 중)
  — 구현 시 **허용 목록(showOnRoutes)** 방식을 쓴다. 새 라우트가 생겼을 때 기본이 "안 보임"이어야 안전하다

## 설계 유의점 (기존 정비와의 접점)

- 하단 고정은 `safe-area-inset-bottom` 을 먹어야 한다 — 뷰포트 정비(#464·#465)의 `dvh`·safe-area 체계 위에 얹는다
- 앱 WebView 에서 이중 여백이 생기지 않는지 확인 (`flutter_inappwebview` 환경)
- 콘텐츠 하단 가림 방지 — 네비가 보이는 화면은 본문에 하단 패딩 추가
- `max-w-app` 안에서 중앙 정렬 (네비도 앱 폭을 따른다)

## 파일 매니페스트 (구현 승인용)

| 파일 | 내용 |
|---|---|
| `src/components/navigation/BottomNav.tsx` (신규) | 탭 5개 렌더·현재 탭 하이라이트·라우트 노출 규칙. 알림 미읽음 뱃지는 기존 `userNotificationUnreadTotal` 재사용 |
| `src/components/navigation/CreateActionSheet.tsx` (신규) | `+` 액션 시트 — 기도카드(그룹 선택 플로우)·감사카드(`/thanks-card/new`)·말씀카드(`/bible-card/new`) |
| `src/App.tsx` (수정) | `AppLayout` 에 `BottomNav` 마운트 + 노출 라우트 목록. 라우트 재작성 없음 |
| 네비 노출 화면들 | 하단 패딩 보정 (개별 페이지 최소 수정) |

**만들지 않는 것**: 새 페이지·새 라우트·baseStore 구조 변경. 기존 진입 경로(드로워·버튼)는 **그대로 둔다** — 네비는 추가이지 대체가 아니다.

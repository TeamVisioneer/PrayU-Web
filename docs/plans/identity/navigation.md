상위: [overview.md](overview.md) · 상태: **구현됨** (#499) — 로컬 검증 완료, staging 확인 대기

## 목표

```
[ 그룹 ]  [  +  ]  [ 프로필 ]              ← v1.0.0 (3탭)
```

> 2026-08-03: `/`(MainPage)는 로그인해도 랜딩 성격이라 탭 화면이 아니다 — 네비를 빼고,
> **홈 탭도 v1.2 까지 뺀다.** 홈 탭이 랜딩을 가리키면 "누르면 네비가 사라지는 화면"이라는 함정이 된다.
> **알림 탭도 함께 유보** — 홈 없는 4탭은 좌우 균형이 안 맞고, 알림은 상단 헤더 벨로 접근 가능하다.
> 코드는 주석으로 남겨 복귀 시 해제만 하면 된다.

지금은 하단 네비게이션이 없고 화면 이동이 페이지마다 다르다(뒤로가기·드로워·버튼).
**v1.0.0 은 "기존 화면을 연결"하는 것까지만** — 새 화면은 만들지 않는다. 목적지가 전부 이미 있다.

## 노출 규칙 (2026-08-03 확장)

**원칙: 탐색 화면에는 네비, 몰입 화면에는 없다.** 구현은 허용 목록(showOnRoutes) — 새 라우트 기본은 "안 보임".

| 구분 | 화면 | 네비 |
|---|---|---|
| 탐색 | `/group` · `/group/:groupId` · `/qt` · `/thanks-card` · `/notice` · `/notifications` · `/profile/me` | ✅ |
| 몰입·랜딩 | `/`(랜딩) · 작성 플로우(기도/말씀/감사카드) · 오늘의기도 · 공유 랜딩 · 콜백 · 약관 · 튜토리얼 · 어드민 · Office | ❌ |

- 로그인 상태에서만 표시. 라벨 없이 **아이콘만** (활성 탭은 흰 pill 하이라이트)
- **화면별 하단 CTA 는 네비 위에 도킹한다** — 그룹 상세의 "오늘의 기도/기도카드 만들기",
  그룹 목록·감사카드의 FAB. `bottom-[calc(5.25rem+env(safe-area-inset-bottom))]` 부근
- CTA 의 진짜 통합(예: 그룹 CTA 를 "오늘" 허브 루틴으로)은 [daily.md](daily.md)(v1.2) 몫이다

## 설계 유의점 (기존 정비와의 접점)

- 하단 고정은 `safe-area-inset-bottom` 을 먹어야 한다 — 뷰포트 정비(#464·#465)의 `dvh`·safe-area 체계 위에 얹는다
- 앱 WebView 에서 이중 여백이 생기지 않는지 확인 (`flutter_inappwebview` 환경)
- 콘텐츠 하단 가림 방지 — 네비가 보이는 화면은 본문에 하단 패딩 추가
- `max-w-app` 안에서 중앙 정렬 (네비도 앱 폭을 따른다)

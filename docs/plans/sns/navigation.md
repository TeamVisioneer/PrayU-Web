# 하단 네비게이션

상위: [overview.md](overview.md) · 상태: **설계 전, 방향만 합의**

## 목표

```
[ 홈 ]  [ 그룹 ]  [  +  ]  [ 알림 ]  [ 프로필 ]
```

지금은 하단 네비게이션이 **없다.** 화면 이동이 페이지마다 다른 방식(뒤로가기·드로워·버튼)이라,
피드·프로필 같은 최상위 목적지가 생기면 갈 길이 없다.

**SNS 전환의 세 축 중 이것만 단독으로 의미가 있다** — 지금 화면들만으로도 이동이 나아진다.
그래서 v1.0.0 에 넣을 후보로 본다 ([overview.md](overview.md) 참조).

## 각 탭이 가리키는 곳

| 탭 | 지금 | 전환 후 |
|---|---|---|
| 홈 | `/` (MainPage) | **피드** ([feed.md](feed.md)). 피드 전까지는 현재 홈 유지 |
| 그룹 | `/group` | 그대로 — 기존 핵심 기능 |
| **+** | 없음 | 생성 진입점. **무엇을 만드는지 결정 필요** (아래) |
| 알림 | 없음(별도 진입) | `notification` 테이블 기반 목록 |
| 프로필 | 없음 | 내 프로필 ([profile-social.md](profile-social.md)) |

## 🔴 `+` 가 무엇을 만드는가 — 결정 필요

지금 만들 수 있는 것이 이미 여럿이다: 기도카드 · 감사카드 · 말씀카드 · 그룹.
`+` 를 누르면 무엇이 나와야 하나?

| 안 | 동작 | 평가 |
|---|---|---|
| **A. 액션 시트** | 탭하면 "기도카드 / 감사카드 / 말씀카드" 선택 시트 | 지금 구조에 가장 잘 맞는다. 새 개념이 필요 없다 |
| B. 게시물 작성 직행 | 새 "게시물" 엔티티 작성 화면 | [feed.md](feed.md) 의 게시물 결정에 종속 |
| C. 맥락 의존 | 보고 있는 탭에 따라 다른 것 생성 | 예측 불가라 권하지 않는다 |

**A 를 권한다** — 게시물 엔티티 결정을 기다리지 않고 지금 만들 수 있고, 나중에 항목만 추가하면 된다.

## 설계 시 유의할 것

- **`--vh`·`dvh`·safe-area** — 뷰포트 계산을 최근에 정비했다(#464·#465). 하단 고정 요소는
  iOS Safari 툴바·홈 인디케이터와 겹치기 쉽다. `viewport-layout-improvement-plan` (archive) 참조
- **앱 WebView** — Flutter 셸 안에서도 동일하게 보여야 한다. 앱 하단 여백과 이중으로 겹치지 않는지 확인
- **`max-w-app`** 토큰 기반 모바일 레이아웃 유지
- **기존 진입 경로 보존** — 드로워·버튼으로 가던 길을 끊지 않는다. 네비게이션은 **추가**이지 대체가 아니다
- 비로그인 상태에서 탭을 누르면? (로그인 유도 vs 숨김) — 결정 필요
